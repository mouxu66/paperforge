# PaperForge 小程序版（零 AI · 工具类 MVP）

把桌面端 PaperForge 的**纯工具类**能力搬进微信小程序：论文导入、收藏、标签、笔记、检索、对比、重复检测、引用核验。

> **零 AI 声明**：本小程序不调用任何大模型 / 生成式 AI。引用核验走 Crossref 权威库做规则比对，重复检测走标题归一化规则匹配。因此**无需算法备案**，《生成式人工智能服务管理暂行办法》不适用。

---

## 0. 小程序简介（mp 后台「小程序介绍」字段，≤120 字，直接复制）

> 零AI论文管理工具，支持从OpenAlex导入元数据、分类收藏、添加标签笔记、关键词检索、两篇对比、重复检测与引用核验。

- 小程序名称建议用「**论文坊**」（与 PaperForge 的 Forge 呼应）；若已定其他名，替换即可。
- 该文案已实测 ≤120 字，可原样粘贴到微信公众平台「小程序介绍」一栏。

## 1. 架构（先看懂再动手）

```
微信小程序（运行壳 + 登录）          腾讯云 云开发 CloudBase（你的环境）
┌──────────────────────────┐        ┌──────────────────────────────────┐
│ 原生 WXML/WXSS/JS 页面     │  wx.cloud.callFunction  │  云函数（8个，云端代理/读写） │
│ pages/ 6 个页面            │ ──────────────────────▶│  paperList / paperSearch      │
│ utils/cloud.js 封装调用    │   HTTPS 内网，免域名白名单│  paperDetail / paperMutate    │
└──────────────────────────┘        │  paperImport(OpenAlex代理)       │
                                     │  paperDuplicates / citationCheck │
                                     │  health                          │
                                     │                                   │
                                     │  云数据库 papers 集合（元数据）   │
                                     │  云存储（未用，PDF 不进小程序）   │
                                     └──────────────────────────────────┘
```

**数据存在哪？** 存在你自己的腾讯云云开发环境里，**不是微信服务器**。微信只是运行壳和登录通道。手机端只留约 10MB 缓存。

**只搬元数据**：标题 / 作者 / 摘要 / 年份 / 期刊 / 分类 / 标签 / 引用数 / DOI。PDF 全文、向量嵌入、图表、审稿评分**不搬**（版权 + 体积 + 小程序用不上）。

## 3. 部署步骤

### 3.1 打开项目
1. 微信开发者工具 → 导入项目 → 目录选本 `miniprogram/` 文件夹。
2. AppID 填你自己的（在 mp 后台「开发管理 → 开发设置」复制）。
3. 后端服务选「微信云开发」。

### 3.2 填环境 ID
打开 `app.js`，把第 3 行改成你的云环境 ID：
```js
const ENV_ID = 'your-cloud-env-id';   // ← 改成云开发控制台左上角显示的环境 ID
```
同时把 `project.config.json` 里的 `"appid": "wxYOURAPPID"` 改成你的 AppID。

### 3.3 部署云函数（8 个）
在 `cloudfunctions/` 目录下，**对每个子目录**右键 →「上传并部署：云端安装依赖」：
```
citationCheck  health  paperDetail  paperDuplicates
paperImport    paperList  paperMutate  paperSearch
```
> 每个函数都带 `package.json`（依赖 `wx-server-sdk: latest`），云端会自动装。

### 3.4 建数据库集合 + 导入你的论文
1. 云开发控制台 → 数据库 → 新建集合，名字固定为 **`papers`**。
2. 集合权限设为「所有用户可读，仅创建者可读写」或「仅管理端可写」（个人库建议前者）。
3. 导入数据：集合 → 导入 → 选 `migration_papers.json`（由 `migrate.py` 从本地库生成）。
   - 没本地库？直接在小程序里点「+ 导入」从 OpenAlex 检索即可，无需此步。

### 3.5 预览 / 真机调试
点开发者工具「编译」→ 模拟器看效果；「预览」扫码到手机实测。

## 4. 从本地桌面端迁移数据（可选）

```bash
cd miniprogram
python migrate.py                         # 默认读 ../mock_api/paperforge_mock.db
python migrate.py --db /path/to/other.db  # 指定库
```
输出 `migration_papers.json`（元数据数组），按 §3.4 导入即可。
脚本只读取、不改写本地库；只取元数据，不碰 PDF / 嵌入 / 图表。

## 5. 功能 ↔ 移植分类对照

| 功能 | 小程序实现 | 类别 |
|------|-----------|------|
| 论文库列表 / 分类浏览 | `paperList` + 首页 | A 可搬 |
| 关键词检索（标题/摘要/作者） | `paperSearch` | A 可搬 |
| 论文详情 | `paperDetail` + 详情页 | A 可搬 |
| 收藏 | `paperMutate.toggleFavorite` | A 可搬 |
| 标签 | `paperMutate.addTag` | A 可搬 |
| 笔记 | `paperMutate.addNote` | A 可搬 |
| 两篇对比 | 对比页（本地渲染） | A 可搬 |
| 重复检测 | `paperDuplicates`（标题归一化） | A 可搬 |
| OpenAlex 导入 | `paperImport`（云端代理，避 CORS/限流） | A 可搬 |

**未搬（需 AI 或本地特权，超出工具类）**：AI 审稿/评分、PDF 全文解析、图表 VLM 解读、本地大模型推理、写作项目协同。这些留在桌面端。

## 6. 审核提交通用要点（工具类更易过）

- **类目**：选「工具 > 办公 / 效率」或「教育 > 工具」，避免选「资讯 / 社交 / 医疗」等严审类目。
- **隐私**：本小程序不收集手机号、不读相册、不定位，隐私协议里如实写「仅存储用户自行录入的论文元数据」。
- **内容**：用户 UGC（笔记）走 `msgSecCheck` 即可；当前笔记为端上直存，若上架前担心，可在 `paperMutate.addNote` 里加一句 `security.msgSecCheck` 校验。
- **零 AI**：审核材料里注明「无生成式 AI 能力」，避免被要求补算法备案。
- **首次提交**：准备 2~3 张功能截图 + 一句话简介，过审通常 1~3 天。
